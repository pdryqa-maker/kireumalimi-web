# 카카오 로그인 계정 설계 (2026-11-14)

## 왜
지금의 '간편 로그인'은 계정이 아니다. 부를 이름과 내 정보, 주유 기록이 그 브라우저의 localStorage에만 있다.
그래서 휴대폰에서 남긴 기록을 노트북에서 볼 수 없고, 같은 이름을 쓰는 두 사람을 서버가 구분할 방법도 없다.

이용자(배재원)의 말: **"기기를 바꿔도 내 정보와 주유 기록이 따라오게."**

이번 작업으로 카카오 로그인으로 진짜 계정을 만든다. 로그인한 사람의 내 정보와 주유 기록은 서버에 보관하고, 어느 기기에서 로그인해도 같은 내용이 보이게 한다.

마감은 2026-11-20(11월 미션 데모)이다.

## 목표
- 카카오로 로그인하고, 로그아웃하고, 회원 탈퇴할 수 있다.
- 로그인하면 계정에 저장된 내 정보와 기록이 그 기기에 보인다. 로그인한 동안 바꾼 것은 계정에도 저장된다.
- 처음 로그인할 때 그 브라우저에 있던 내 정보와 기록을 계정으로 옮긴다. 지금 쓰던 사람의 기록을 잃지 않게 한다.
- 로그인하지 않아도 지금처럼 모든 기능을 쓴다(게스트).
- 탈퇴하면 서버 데이터를 바로 지운다. 카카오 쪽에서 연결을 끊어도 지운다.
- 개인정보 처리방침(/privacy)에 새로 생기는 수집·보관을 적는다.

## 하지 않는 것
- 카카오톡으로 알림 보내기('나에게 보내기'). 로그인이 들어오면 가능해지지만 이번 범위가 아니다.
- 카카오 말고 다른 로그인(구글, 네이버, 이메일·비밀번호).
- 같은 계정을 여러 기기에서 동시에 고칠 때 칸 단위로 합치기. 마지막에 저장한 쪽을 쓴다(아래 '동기화').
- 호출 제한(rateLimit)을 계정 단위로 바꾸거나 Redis로 옮기기. 나중에 할 수 있게 열어만 둔다.
- 채팅 대화 내용을 저장하기. 지금도 저장하지 않는다.

## 이렇게 되면 실패다
- 로그인했다가 기록이 사라진다. 처음 로그인할 때 합치다 잃는 경우, 다른 계정 기록과 섞이는 경우가 여기에 든다.
- 같이 쓰는 PC에서 로그아웃했는데 다음 사람이 앞사람의 기록을 보거나, '카카오 로그인'만 눌러 앞사람 계정으로 들어간다.
- 탈퇴했는데 서버에 데이터가 남는다.
- 로그인하지 않은 사람이 무언가를 못 쓰게 된다.
- 키와 시크릿이 코드, 커밋, 채팅, 브라우저로 새어 나간다.

## 제약
- Next.js 16(App Router, `cacheComponents: true`), React 19, TypeScript strict, Tailwind 4. 코드를 쓰기 전에 `node_modules/next/dist/docs/`에서 쿠키와 라우트 핸들러 사용법을 확인한다(AGENTS.md).
- Vercel 프로젝트는 팀원 계정에 있다. DB 연결과 환경변수는 팀원이 넣는다. 이용자는 보호된 프리뷰를 열지 못한다.
- 카카오에는 미리 등록한 리다이렉트 URI만 쓸 수 있다. 프리뷰 주소는 매번 바뀌므로 로그인 시험은 localhost와 운영 주소에서만 된다.
- main 병합은 곧 운영 배포다. 이용자가 매번 분명히 허락할 때만 병합한다.
- 키와 시크릿은 `.env.local`과 Vercel 환경변수에만 둔다. `.env.example`에는 이름만 적는다.
- 같은 파일을 고치는 다른 작업이 둘 있다(아래 '다른 작업과 맞추기').

## 방법 (고른 것: 직접 구현 + Upstash Redis)
로그인 방식 세 가지와 저장소 세 가지를 견주었고, 이용자가 추천안을 골랐다.

| 로그인 방식 | 장점 | 단점 |
|---|---|---|
| **A. 직접 구현 (선택)** | 새 라이브러리 없이 경로 몇 개로 끝난다. 카카오 토큰을 서버에 보관하지 않는다. 이 저장소의 손으로 짠 작은 코드와 결이 같다. | 위조 방지(state 확인, 쿠키 서명)를 직접 짜고 테스트해야 한다. |
| B. Auth.js v5 | 카카오 provider가 들어 있다. | 아직 beta(5.0.0-beta.32)이고 사실상 유지 관리 상태다. 연결 끊기·탈퇴는 결국 직접 짠다. |
| C. Better Auth | 활발하고 카카오를 지원한다. | 자체 테이블 4개와 마이그레이션이 든다. 기본 동의 항목에 이메일이 있어 빼야 한다. 카카오 하나만 쓰기에는 무겁다. |

| 저장소 | 장점 | 단점 |
|---|---|---|
| **가. Upstash Redis (선택)** | 브라우저에 저장하는 JSON을 그대로 담는다. 스키마가 없고 무료 등급으로 충분하다. Vercel 저장소 탭에서 연결하면 환경변수가 들어간다. | 서울 지역이 없어 도쿄(ap-northeast-1)를 쓴다. SQL 통계는 어렵다. |
| 나. Neon Postgres | 표로 통계를 뽑기 좋다. | 테이블 설계와 마이그레이션이 더 든다. |
| 다. Supabase | 서울 지역이 있고 카카오 로그인도 준다. | Supabase 로그인·SDK로 바뀌어 손댈 곳이 많다. Claude API와 Vercel이 해외라 국외 이전 고지는 어차피 남는다. |

## 정한 것 (이용자와 함께)
- 계정에 저장할 것: 내 정보와 주유 기록.
- 로그아웃하면 그 브라우저에서 내 정보와 기록을 지운다. 계정에는 남고, 다시 로그인하면 돌아온다(이용자 확인).
- 로그인하지 않은 사람은 지금처럼 다 쓴다.

## 빌더의 판단으로 정한 것 (이용자 검토 대상)
아래는 내가 제안해 대화에서 설명한 것이다. 반대가 없어 그대로 간다.
- 알림 조건과 예보 켜기 설정도 계정에 올린다. 양이 작고, 기기를 바꿨을 때 이것만 사라지면 어색하다.
- 카카오에서는 회원번호만 꼭 받는다. 닉네임은 선택 동의로 받아 '부를 이름' 기본값으로 쓴다. 이메일·전화번호·프로필 사진은 받지 않는다.
- 이름만 넣는 '간편 로그인'은 없앤다. 그 자리에 '카카오로 로그인'을 둔다. 내 정보 입력 화면은 게스트도 쓸 수 있고, 게스트가 저장하면 그 브라우저에만 남는다.
- 처음 로그인할 때 합치는 규칙은 '처음 로그인할 때 합치기'에 있다.

이 문서에서 처음 정한 것은 '[빌더 판단]'으로 표시한다.

## 사용자가 보는 것

### 로그인 화면(/login, 게스트)
```
 ( 불꽃 )  로그인
          카카오로 로그인하면 다른 기기에서도 내 정보와 주유 기록이 그대로 보여요.
 ┌──────────────────────────────────────┐
 │ [말풍선]  카카오 로그인                │   ← 카카오 디자인 가이드의 노란 버튼(#FEE500)
 └──────────────────────────────────────┘
 로그인하지 않아도 아래 내 정보를 이 브라우저에만 저장해 쓸 수 있어요.

 부를 이름 / 내 위치 / 내 차 …   (지금 입력 화면 그대로)
 [이 정보로 시작하기]
 개인정보 처리방침
```

### 내 정보 화면(/login, 로그인한 사람)
```
 ( 재 )  내 정보
        카카오 계정으로 로그인했어요. 어느 기기에서 로그인해도 같은 정보가 보여요.
 부를 이름 / 내 위치 / 내 차 …
 [저장하고 돌아가기]   로그아웃
 ──────────
 회원 탈퇴   ← 작게. 누르면 확인: "계정에 저장된 내 정보와 주유 기록 N건을 지우고 카카오 연결을 끊어요. 되돌릴 수 없어요." [탈퇴하기] [취소]
```

### 머리글(AppShell)
- 로그인한 사람: 지금처럼 이름 첫 글자 아바타. 누르면 내 정보 화면이 열린다.
- 게스트: '로그인' 버튼. 이름을 저장해 둔 게스트도 마찬가지다. [빌더 판단] '로그인'은 이제 카카오 계정을 뜻한다.

### 안내 한 줄
- 처음 로그인하고 합친 뒤: "이 브라우저에 있던 주유 기록 3건을 계정에 합쳤어요." 합칠 것이 없으면 "카카오 계정으로 로그인했어요."
- 로그아웃 뒤: "로그아웃했어요. 이 브라우저에서 내 정보와 기록을 지웠어요(계정에는 남아 있어요)."
- 탈퇴 뒤: "탈퇴했어요. 계정의 내 정보와 기록을 모두 지웠어요."
- 로그인 취소나 실패: "카카오 로그인을 마치지 못했어요. 다시 눌러 주세요."
- 안내는 내 정보 화면이나 첫 화면 위쪽에 한 번 보이고 사라진다. 자리는 빌더가 정한다.

## 동작

### 로그인
1. '카카오 로그인' → `GET /api/auth/kakao`
   - 무작위 state를 만들어 10분짜리 httpOnly 쿠키에 넣는다.
   - 카카오 인가 주소(`https://kauth.kakao.com/oauth/authorize`)로 보낸다. 넘기는 값: `client_id`, `redirect_uri`, `response_type=code`, `state`.
2. 카카오가 `GET /api/auth/kakao/callback?code&state`로 돌려보낸다.
   - state 쿠키와 비교한다(시간 차이로 새지 않는 비교). 맞지 않으면 로그인하지 않는다.
   - 토큰 주소로 code를 바꾼다. 넘기는 값: `client_id`, `client_secret`, `redirect_uri`, `code`.
   - `GET https://kapi.kakao.com/v2/user/me`로 회원번호(id)와 닉네임(동의했으면)을 받는다.
   - **카카오 토큰은 어디에도 저장하지 않고 버린다.**
3. 우리 세션 쿠키를 넣고 `/login?account=welcome`으로 보낸다.
   - 사용자가 취소했거나(error=access_denied) 실패하면 `/login?account=failed`.
- `redirect_uri`는 요청이 온 주소의 origin + `/api/auth/kakao/callback`로 만든다. 등록한 주소(localhost, 운영)에서만 성공한다.
- 세션 쿠키 [빌더 판단]
  - 내용: `{ sub: 카카오 회원번호, nick: 닉네임 또는 빈 값, iat, exp }`. HMAC-SHA256(`AUTH_SECRET`)로 서명한다.
  - 속성: httpOnly, `SameSite=Lax`, 운영에서는 Secure, `Path=/`.
  - 기간: 30일. 늘려 주지 않는다. 다시 로그인은 카카오 버튼 한 번이면 된다.
- 계정 API(`/api/account`)는 세션 쿠키만 믿는다. 바꾸는 요청(PUT, DELETE, 로그아웃 POST)은 `Origin` 머리글이 우리 주소인지도 확인한다. [빌더 판단]

### 서버 저장(Upstash Redis)
- 사람마다 해시 하나를 둔다. 키는 `acct:{카카오 회원번호}`.
- 칸: `profile`, `fills`, `ledger`, `alerts`, `watch`(각각 JSON 글자), `meta`(`{ createdAt, updatedAt }`).
- 브라우저 저장소 키와 짝: `kireumalimi.profile` / `.fills` / `.ledger` / `.alerts` / `.watch`.
- 계정에 올리지 않는 것: `kireumalimi.vsArea`, `kireumalimi.areaPrice` 같은 임시 저장값. 다른 작업이 더하는 캐시도 같다.
- 서버는 받은 값을 지금의 검사 함수로 다시 검사해 저장한다. `cleanProfile`, fills 검사, `cleanLedger(…, MAX_SAVED_LEDGER)`, `parseAlerts`, `parseWatch`.
  - 그래서 다른 작업이 Profile에 칸을 더해도 `cleanProfile`만 고치면 계정에도 반영된다.
- 칸 하나의 크기 한도는 64KB. 넘으면 413. 장부 100번이 약 15KB다.
- 보관 기간 [빌더 판단]: 탈퇴하거나 카카오에서 연결을 끊을 때까지. 다만 1년 동안 한 번도 쓰지 않으면 자동으로 지운다. 읽거나 쓸 때마다 키 만료를 1년 뒤로 미룬다(EXPIRE).
- 환경변수: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`. Vercel 연동으로 넣으면 이름이 `KV_REST_API_URL`, `KV_REST_API_TOKEN`일 수 있어 둘 다 읽는다.
- 클라이언트는 `@upstash/redis`(REST, 서버리스용)를 쓴다. [빌더 판단]

### 계정 API
- `GET /api/account`
  - 게스트: `{ account: null }`.
  - 로그인: `{ account: { nickname }, data: { profile?, fills?, ledger?, alerts?, watch? } }`.
  - 회원번호는 브라우저에 보내지 않는다. 대신 `tag`를 보낸다. `tag`는 `HMAC(AUTH_SECRET, 회원번호 + ":" + meta.createdAt)`의 앞 16자이고, 같은 계정인지 구분하는 데 쓴다.
    - createdAt을 섞는 이유: 탈퇴 뒤 다시 가입하면 새 계정으로 친다. 그래서 탈퇴 전에 로그인해 둔 다른 기기의 옛 사본이 새 계정에 다시 올라가지 않는다.
  - 세션은 맞는데 Redis 키가 없으면 401을 주고 세션 쿠키를 지운다. 웹훅 삭제나 1년 자동 삭제 뒤가 이 경우다.
    - 키는 로그인 콜백에서 `HSETNX acct:{id} meta {createdAt…}`로 먼저 만든다. 그래서 '갓 가입해 아무것도 없는 계정'과 '지워진 계정'이 구분된다.
  - Redis가 응답하지 않으면 503을 준다. 브라우저는 이때 아무것도 지우지 않는다.
- `PUT /api/account` `{ tag, data: { profile?: …, fills?: …, … } }`: 보낸 칸만 검사해 덮어쓴다. `meta.updatedAt`을 갱신한다.
  - `tag`가 지금 계정의 tag와 다르면 409로 거절한다. [빌더 판단]
  - 막으려는 경우: 다른 탭에 대기 중인 올리기가 있는데 그사이 로그아웃하고 다른 계정으로 로그인했다. 그 올리기가 새 계정에 들어가면 안 된다.
  - 처음 합치기의 PUT은 아직 tag가 없으므로 GET으로 받은 tag를 그대로 보낸다.
- `DELETE /api/account`(탈퇴)
  1. Redis 키를 지운다.
  2. 카카오 연결 끊기(`POST https://kapi.kakao.com/v1/user/unlink`, `Authorization: KakaoAK {어드민 키}`, `target_id_type=user_id`, `target_id`)를 부른다.
  3. 세션 쿠키를 지운다.
  - 연결 끊기가 실패해도 데이터는 이미 지웠으므로 성공으로 답한다. 답에 "카카오 설정에서 연결을 끊어 주세요"를 붙이고 서버 로그에 남긴다.
- `POST /api/auth/logout`: 세션 쿠키를 지운다. 응답에 카카오 로그아웃 주소를 담는다(아래 '로그아웃').
- `/api/auth/kakao/unlink`(카카오 연결 끊기 웹훅, GET·POST)
  - `Authorization: KakaoAK {어드민 키}`가 맞을 때만 `user_id`의 키를 지운다.
  - 무엇이 와도 3초 안에 200으로 답한다(카카오 문서).
- 호출 제한: 기존 `limitByClient`에 `account` 한도를 더한다(10분에 120번). [빌더 판단]

### 동기화(브라우저 ↔ 계정)
화면 코드는 그대로 브라우저 저장소를 읽고 쓴다. `browserStore.write` 뒤에 계정 동기화 층 하나만 끼운다.

- **동기화 상태**: 브라우저 키 `kireumalimi.sync`에 `{ tag, dirty: [칸 이름…] }`을 둔다.
  - `tag`: 이 브라우저의 데이터가 어느 계정 것인지.
  - `dirty`: 이 브라우저에서 바꿨지만 아직 계정에 못 올린 칸.
- **쓸 때**: 동기화할 키(위 다섯 개)에 쓰면 그 칸을 dirty에 넣는다. 로그인 상태면 1.5초 모아서 `PUT`한다. 성공하면 dirty에서 뺀다. 실패하면 남겨 두고 다음 쓰기·화면 열기·창 다시 보기 때 다시 보낸다.
- **열 때와 창을 다시 볼 때**(1분에 한 번까지): `GET /api/account`.
  - 게스트(`tag` 없음)면 아무것도 안 한다.
  - 세션만 끝났고(30일) `tag`가 남아 있으면 이 브라우저의 사본을 그대로 둔다. [빌더 판단]
    - "로그인 기간이 끝났어요. 다시 로그인하면 계정과 맞춰요."를 한 번 보인다.
    - 그동안 바꾼 것은 dirty로 쌓인다. 같은 계정으로 다시 로그인하면 올린다. 다른 계정으로 로그인하면 아래 규칙 1로 먼저 지운다.
    - 이렇게 하는 이유: 세션이 끝난 것은 이용자가 의도한 일이 아니다. 자기 휴대폰에서 30일 만에 기록이 사라져 보이면 안 된다. 같이 쓰는 PC는 로그아웃 버튼이 지운다.
  - 401(계정이 지워짐)이면 dirty가 있어도 동기화 키와 `tag`를 모두 지운다.
  - 로그인했고 `tag`가 같으면, dirty가 아닌 칸은 계정 값으로 바꾸고 dirty 칸은 올린다.
    - 합치기에서 다섯 칸을 한 번의 HSET으로 올리므로, 같은 tag인 계정에는 다섯 칸이 늘 있다.
  - 로그인했는데 `tag`가 없거나 다르면 '처음 로그인할 때 합치기'로 간다.
- 두 기기에서 같은 칸을 거의 같은 때 고치면 나중에 올린 쪽이 남는다(칸 단위 마지막 저장).
- 로그인 상태(계정 있음, 닉네임)는 `useAccount()` 훅이 화면에 준다. 첫 그림은 '모름'이고 GET이 끝나면 정해진다. 머리글이 깜빡이지 않게 모를 때는 지금의 아바타 자리 표시를 쓴다.

### 처음 로그인할 때 합치기
`tag`가 없거나 다를 때 한 번 한다.
1. **`tag`가 다른 계정 것이면** 이 브라우저의 동기화 키를 먼저 비우고 2로 간다. 앞사람이 로그아웃하지 않아 세션만 끝났거나, 탈퇴 뒤 다시 가입한 경우다. 다른 계정의 기록은 섞지 않는다.
2. **`tag`가 없으면**(게스트로 쓰던 브라우저) 이 브라우저 값과 계정 값을 합친다.
   - `profile`: 계정에 '채운' 내 정보가 있으면 계정 것을 쓴다. 없으면 이 브라우저 것을 쓴다.
     - '채운'의 뜻 [빌더 판단]: 부를 이름을 빼고 `GUEST`(기본값)와 다른 칸이 하나라도 있다.
     - 이렇게 정하는 이유가 있다. 합치기는 다섯 칸을 늘 올리고 `cleanProfile`은 기본값을 채운 객체를 돌려준다. 그래서 빈 노트북에서 먼저 로그인하면 계정에는 '기본값 + 닉네임'만 들어간다. 그 뒤 휴대폰(게스트로 차·위치를 넣어 둠)에서 로그인할 때 그 기본값이 휴대폰 정보를 덮으면 안 된다.
     - 이름은 이렇게 고른다: 계정 이름 → 이 브라우저 이름 → 카카오 닉네임(12자로 자르고 `cleanText`).
   - `ledger`: 날짜로 합친다. 같은 날이 양쪽에 있으면 계정 것을 쓴다. 최근 100번까지(`cleanLedger`).
   - `fills`: 날짜로 합친다. 같은 날은 계정 것을 쓴다. 지금처럼 최근 5번까지(`MAX_RECORDS`).
   - `alerts`: 합치고 같은 조건(유종·지역·금액)은 하나만 둔다. 최대 5개, 최근 것부터 남긴다.
   - `watch`: 계정에 켜 둔 것이 하나라도 있으면 계정 것을 쓴다. 다 꺼져 있으면 이 브라우저 것을 쓴다(profile과 같은 이유).
3. 합친 값을 브라우저에 쓰고 다섯 칸을 모두 `PUT`한다. 성공하면 `tag`를 저장하고 dirty를 비운다.
   - 실패하면 `tag`를 저장하지 않는다. 다음에 열 때 2를 다시 한다. 합치기는 여러 번 해도 결과가 같게 만든다.
4. 안내 한 줄에 이 브라우저에서 계정으로 새로 들어간 주유 기록 수를 보인다.

합치기는 순수 함수로 따로 둔다(`mergeAccount(local, remote) → { merged, addedFills }`). 테스트하기 쉽게 하려는 것이다.

### 로그아웃
1. 아직 못 올린 dirty가 있으면 먼저 올린다. 세션 쿠키가 있어야 올릴 수 있으므로 쿠키를 지우기 전에 한다.
   - 올리지 못하면 바로 지우지 않는다. 이렇게 묻는다: "아직 계정에 못 올린 기록이 있어요. 지금 로그아웃하면 이 기록은 사라져요." [다시 시도] [그래도 로그아웃]. [빌더 판단]
   - 기록을 잃는 것과 같이 쓰는 PC에 남기는 것이 부딪히는 유일한 경우다. 그래서 이용자가 고르게 한다.
2. `POST /api/auth/logout` → 세션 쿠키를 지운다.
3. 브라우저에서 동기화 키 다섯 개와 `kireumalimi.sync`를 지운다.
4. 카카오계정 로그아웃 주소로 보낸다: `https://kauth.kakao.com/oauth/logout?client_id=…&logout_redirect_uri={origin}/?account=loggedout`. [빌더 판단]
   - 카카오가 "카카오계정도 함께 로그아웃할지" 화면을 보인다. 같이 쓰는 PC에서 다음 사람이 '카카오 로그인'만 눌러 앞사람으로 들어가는 것을 막는다.
   - 카카오 세션이 없거나 카카오톡 안 브라우저면 바로 돌아온다(카카오 문서).
   - 로그아웃 리다이렉트 URI를 카카오에 등록해야 한다(설정 안내 참고).

### 회원 탈퇴
1. 내 정보 화면의 '회원 탈퇴' → 확인 창 → `DELETE /api/account`.
2. 성공하면 브라우저의 동기화 키와 `kireumalimi.sync`를 지우고 첫 화면으로 간다. 안내 한 줄을 보인다.
3. 카카오 설정(카카오계정 > 연결된 서비스 관리)에서 연결을 끊으면 웹훅으로 서버 데이터를 지운다.
   - 로그인해 둔 다른 기기의 사본은 그 기기에서 다음에 열 때 지운다. 그때 `GET`이 401을 준다('계정 API' 참고).
   - 다른 기기에서 탈퇴한 경우도 같다.

### 챗봇과 다른 화면
- 챗봇은 지금처럼 브라우저의 내 정보를 보낸다(`signedIn(profile)` = 부를 이름이 있음). 계정이 생겨도 이 규칙은 그대로다.
- 카카오로 로그인하면 이름이 닉네임으로 채워지므로 지금처럼 이름으로 불린다. 서버는 채팅 때 DB를 읽지 않는다.
- `signedIn`이라는 이름은 이제 '내 정보를 저장함'을 뜻한다. 이름을 바꾸면 다른 작업과 겹치므로 그대로 두고 주석만 고친다. [빌더 판단]
- 내 정보 화면의 지금 '로그아웃' 버튼(게스트가 저장한 이름 지우기)은 게스트에게는 '이 브라우저의 내 정보 지우기'로 이름을 바꾼다. 하는 일은 같다. [빌더 판단]

## 이용자와 팀원이 할 일 (내가 대신 하지 않는다)
자세한 클릭 순서는 PR 본문과 마지막 안내에 적는다.
1. **카카오 디벨로퍼스(이용자)**
   - 앱을 만들고 카카오 로그인을 켠다.
   - 리다이렉트 URI 두 개를 등록한다: `http://localhost:3000/api/auth/kakao/callback`, `https://kireumalimi-web.vercel.app/api/auth/kakao/callback`.
   - 로그아웃 리다이렉트 URI 두 개를 등록한다: `http://localhost:3000/?account=loggedout`, 운영 주소 같은 경로.
   - 동의 항목에서 닉네임을 '선택 동의'로 둔다.
   - 클라이언트 시크릿을 켠다.
   - 연결 끊기 웹훅에 `https://kireumalimi-web.vercel.app/api/auth/kakao/unlink`를 등록한다.
   - 웹 플랫폼 사이트 도메인에 두 주소를 등록한다.
2. **Upstash(팀원이 Vercel 저장소 탭에서, 또는 이용자가 직접)**: Redis 데이터베이스를 도쿄 지역으로 만든다.
3. **환경변수**: 아래 값을 `.env.local`(이용자)과 Vercel(팀원)에 넣는다.
   - `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `KAKAO_ADMIN_KEY`
   - `AUTH_SECRET`: 32바이트 이상 무작위. 각자 터미널에서 만든다.
   - `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`

키가 없을 때의 동작 [빌더 판단]: 카카오 키나 Redis 값이 없으면 로그인 버튼 자리에 "카카오 로그인 준비 중이에요"를 보이고, 나머지는 게스트로 그대로 동작한다. 키를 넣기 전에 병합해도 사이트가 깨지지 않게 하려는 것이다.

  - 이 PR이 준비됐는데 guest-location이 아직 병합되지 않았으면 그때 이용자에게 순서를 묻는다. [빌더 판단]
  - 키가 없으면 로그인이 '준비 중'이라 데이터를 받지 않는다. 키를 넣기 전에 병합하는 것은 괜찮다.
- 11/20 데모에서 운영 사이트로 로그인을 보이려면 카카오 앱, Upstash, Vercel 환경변수가 그 전에 준비돼야 한다. 그래서 설정 안내는 구현을 기다리지 않고 계획 단계에서 먼저 드린다.

## 시험
- **순수 함수 단위 시험**(node 스크립트, 기존 `$S/apptest` 방식)
  - 세션 서명·검증: 위조, 만료, 다른 시크릿.
  - `mergeAccount`: 빈 계정, 빈 브라우저, 같은 날, 다른 계정 tag, 두 번 해도 같은지.
  - 계정 칸 검사: 크기 한도, 잘못된 값.
- **끝에서 끝 시험(로컬)**
  - 가짜 카카오 서버(인가·토큰·user/me·unlink)와 가짜 Upstash REST 서버를 띄운다.
  - 카카오·Upstash 주소는 개발 환경에서만 환경변수로 바꿀 수 있게 한다. [빌더 판단]
  - 시나리오: 게스트 기록 → 로그인 → 합치기 → 다른 브라우저(새 프로필)로 로그인 → 같은 기록 보임 → 로그아웃 → 지워짐 → 다시 로그인 → 돌아옴 → 탈퇴 → 서버 키 없음 → 웹훅 삭제.
- **진짜 카카오 시험**
  - 이용자가 `.env.local`에 키를 넣은 뒤 localhost에서 한다. 카카오 계정 로그인은 이용자가 직접 한다.
  - 운영 확인은 병합 뒤 이용자가 한다.
- 챗봇 실제 질문은 Claude API 비용이 든다. 이 작업은 챗봇을 바꾸지 않으므로 실제 질문 시험은 하지 않는다. 필요하면 먼저 알린다.
